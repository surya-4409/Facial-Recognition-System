## 📋 Overview

This project implements an end-to-end facial **verification** (1:1 matching) system with a comprehensive **algorithmic fairness audit**. It demonstrates the full responsible AI engineering lifecycle:

1. **Model Development** — Fine-tune FaceNet (InceptionResnetV1, VGGFace2) with Triplet Loss
2. **Fairness Audit** — Disaggregated FAR/FRR across gender × age × skin tone subgroups
3. **Bias Analysis** — Identify worst-performing groups and hypothesize root causes
4. **Mitigation** — Post-processing threshold calibration to reduce FRR disparity
5. **Reporting** — Automated deployment readiness memo (PDF)

The work is motivated by real-world regulatory requirements (EU AI Act, NYC Local Law 144) and foundational academic work (Buolamwini & Gebru, "Gender Shades", 2018).

## 🧑‍💻 Technical Architecture

### Model: FaceNet InceptionResnetV1

- **Backbone**: InceptionResnetV1 pretrained on VGGFace2 (3.3M face images)
- **Embedding**: 512-dimensional L2-normalized face embeddings
- **Verification**: Cosine similarity between embedding pairs
- **Library**: [`facenet-pytorch`](https://github.com/timesler/facenet-pytorch)

### Training: Triplet Loss with Semi-Hard Negative Mining

```
Loss = max(0, ||f(anchor) - f(positive)||² - ||f(anchor) - f(negative)||² + margin)
```

- Margin: 0.2 (tunable via environment)
- Optimizer: Adam (lr=1e-4) with Cosine LR schedule
- Negative mining: random negatives from different identities within same subgroup

### Verification Pipeline

```
Image A ──► FaceNet ──► Embedding A ──►
                                        Cosine Similarity ──► [≥ threshold?] ──► Match/Non-match
Image B ──► FaceNet ──► Embedding B ──►
```

## 📊 Demographic Group Definitions

### Dataset: FairFace

FairFace (Kärkkäinen & Joo, 2021) contains 108,501 face images annotated with:
- **7 race categories**: White, Black, Indian, East Asian, Southeast Asian, Middle Eastern, Latino_Hispanic
- **Binary gender**: Male, Female
- **9 age groups**: 0-2, 3-9, 10-19, 20-29, 30-39, 40-49, 50-59, 60-69, more than 70

### Skin Tone Mapping (Race → Skin Tone Scale)

Since FairFace does not include Fitzpatrick scale labels, we use a race-label proxy:

| FairFace Race Label | Mapped Skin Tone | Rationale |
|---|---|---|
| White | Light | Generally corresponds to ITA > 28° |
| East Asian | Light | Generally corresponds to ITA > 10° |
| Indian | Medium | Broad ITA range (−10° to +28°) |
| Latino_Hispanic | Medium | Highly variable; medium approximation |
| Southeast Asian | Medium | Variable; medium approximation |
| Middle Eastern | Medium | Variable; medium approximation |
| Black | Dark | Generally corresponds to ITA < −30° |

**⚠️ Acknowledged Limitation**: This is a coarse approximation. Race and skin tone are distinct constructs. Within each race category, skin tone varies significantly. A more rigorous audit would use individual-level Fitzpatrick classification or ITA measurement. This limitation is documented in `results/analysis.json`.

### Age Bins

FairFace's 9 age groups are collapsed into 4 bins per project specification:

| Bin | FairFace Groups |
|---|---|
| 0-19 | 0-2, 3-9, 10-19 |
| 20-39 | 20-29, 30-39 |
| 40-59 | 40-49, 50-59 |
| 60+ | 60-69, more than 70 |

## ⚖️ Bias Mitigation Strategy

### Chosen Strategy: Post-Processing Threshold Calibration

**Rationale**: Post-processing is the most transparent and non-invasive mitigation technique. It does not require access to training data or model internals, making it suitable for auditing pre-trained models. It directly addresses the observed symptom (disparate FRR) and its effects are interpretable.

**Algorithm**:
1. For each demographic subgroup, collect validation set similarity scores for positive/negative pairs
2. Find the per-group threshold that minimizes FRR subject to FAR ≤ (global_FAR + 5%)
3. Apply group-specific thresholds during inference/audit

**Trade-offs**:
- ✅ Reduces FRR disparity across groups without retraining
- ✅ Transparent and auditable — thresholds are explicit and stored in `overall_metrics.json`
- ⚠️ May slightly increase FAR for some groups (bounded by tolerance parameter)
- ⚠️ Requires knowledge of sensitive attributes at inference time
- ⚠️ Does not address root causes in training data distribution

**Alternative strategies considered**:
- *Pre-processing (re-sampling)*: Would require retraining; better for addressing root causes
- *In-processing (adversarial debiasing)*: Most powerful but computationally expensive and complex
- *Post-processing (chosen)*: Best fit for a fairness audit where we evaluate an existing model

## 📈 Key Metrics

| Metric | Description |
|---|---|
| **FAR** (False Accept Rate) | Rate at which different-person pairs are incorrectly accepted |
| **FRR** (False Reject Rate) | Rate at which same-person pairs are incorrectly rejected |
| **FRR Disparity** | Max FRR − Min FRR across all demographic subgroups |
| **Balanced Accuracy** | 1 − (mean FAR + mean FRR) / 2 across subgroups |
